# E001｜真人付费路线审计

> 状态：待杨补充目标人群、价格并授权外部触达  
> 目的：取得首批非人情预付与执行行为，不验证软件产品

## 一、核心问题

在没有外部强制、且明确不保证赚钱结果时，目标用户是否愿意在收到完整报告前预付，购买一次候选路线筛选和最小市场验证设计？

## 二、最小服务

本实验不卖“确定路线”，只交付：

1. 用户当前持有的时间、技能、渠道、本金和限制；
2. 最多3条由用户提出或共同形成的候选路线；
3. 对每条路线列出要求、缺口、关键未知和不可核部分；
4. 选择1条优先验证路线，或明确当前不应投入；
5. 给出7—14天侦察动作、时间盒、现金上限、继续条件和停止条件；
6. 一次约定时间的复盘。

不交付死亡率、确定性分数、收入预测或完整创业计划。

## 三、必须由杨在触达前填写

| 字段 | 当前状态 |

| 明确排除的人群 | `待杨确定` |

没有填写价格和目标人群，不开始招募。

## 四、样本结构

### A组：前三名校准样本

目的只是发现：用户听不懂什么、为什么拒绝、交付是否做得出来、实际耗时多少。

每次允许修改：用户描述、报价、交付边界。修改后记录版本号。A组不用于方向升降级，也不与B组合并计算转化率。

### B组：5—10名正式样本

有效条件：

- 非亲属、非员工、非项目合作者；
- 不以未来利益交换购买；
- 符合统一目标人群；
- 看到相同服务边界和固定价格；
- 在完整报告交付前自行支付；
- 免费咨询、口头认可和事后打赏不计预付。

## 五、逐人记录字段

只用代号：

| 字段 | 记录要求 |
|---|---|
| 样本编号 | A01或B01等 |
| 来源渠道 | 不记录可识别身份 |
| 是否符合人群 | 是/否及理由 |
| 报价版本 | 稳定编号 |
| 是否预付 | 金额与时间；支付凭证在仓库外 |
| 拒绝原因 | 尽量使用用户原话，匿名 |
| 实际交付小时 | 拆分访谈、研究、报告、复盘 |
| 建议中的未知 | 明确哪些没有数据 |
| 是否执行侦察动作 | 行为与日期 |
| 用户承担成本 | 时间、现金、联系客户等 |
| 是否获得市场信号 | 询价、回复、订单或明确拒绝 |
| 退款/争议 | 事实经过 |
| 后续付费/转介绍 | 仅记真实行为 |

## 六、预先登记的裁决

完成10名有效B组或到达30天复核点时裁决：

- `0/10预付`：停止产品化，退回假设层；不继续建设路线库或原型。
- `1—2/10预付`：证据模糊；只允许一次预先登记的人群或报价迭代，然后重新建组，不能合并旧数据。
- `≥3/10预付`：只说明存在初步购买；进入人工交付质量、执行和复购验证，不直接开发软件。

无论预付多少，如果交付长期需要杨本人进行不可拆分判断，必须标记“个人手艺风险”。

## 七、反证问题

每次复盘强制回答：

1. 用户究竟为路线判断、陪伴、信息、希望还是与杨的关系付费？
2. 不使用“AI”或“赚钱”措辞，购买是否仍成立？
3. 通用模型免费输出能否达到相同效果？
4. 真正产生价值的是判断，还是用户被迫去联系客户？
5. 不赚钱或被建议停止时，用户是否仍认为服务值得？
6. 实际人工成本能否被当前价格覆盖？

## 八、当前下一动作
