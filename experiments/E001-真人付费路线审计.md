# E001｜真人付费路线审计（草案，未启动）

> 状态：暂停在设计前
>
> 启动前提：E000至少形成一次可审计校准记录；杨明确一个购买情境、风险承担方式和外部触达动作，并另行授权
>
> 当前用途：保留未来可能的行为验证结构，不倒推现在的产品、人群或价格

## 一、它能证明什么，不能证明什么

若未来测试“路线诊断／验证服务”，E001检验的是：在没有外部强制、明确不保证赚钱结果、且交付边界固定时，一个具体购买情境中的付款方是否产生真实购买行为。

- 一次非人情预付：只证明发生了一次购买；
- `0/N`：不能直接解释为“没有需求”，可能混有信任、价格、边界、时点或支付摩擦；
- 交付后付款：不能证明用户最初愿意承担风险；
- 满意、执行、市场信号、复购和规模：必须另行记录，不能由付款外推。

若未来形态转向社区、案例媒体、创业工作室或工具，本实验必须重写。

## 三、启动后必须冻结的内容

- 购买情境、目标与排除条件；
- 价格、交付、退款和唯一风险承担方式；
- 触达渠道、话术、样本边界和停止条件；
- 杨的单客工时上限与可接受关系损耗；
- 原始记录字段与拒绝归因问句。

小样本用于暴露机制和归因，不作A/B统计，不把校准接触与正式购买混算。

## 四、报价当刻的原始记录

先保留原话和时间，再编码，禁止事后只写“没需求”：

1. 对方对交付的复述；
2. 报价后的首个原话；
3. 是否还价、追问、要求样例或提出替代方案；
4. 首次响应时间；
5. 之后是否主动回流、何时回流；
6. 是否付款、退款及理由。

拒绝后使用预写判别问句，至少区分：

| 可能原因 | 判别问句 |
|---|---|
| 不需要 | 过去12个月，你上一次为完成同一任务付钱或承担显著成本是什么时候？ |
| 需要但不信任提供者 | 如果由你已经信任、且能力相当的人提供同样服务，你会考虑买吗？为什么？ |
| 价格不对 | 在交付不变的情况下，什么价格你会认真考虑？ |
| 交付边界不清 | 你原以为付款后会拿到什么？ |
| 时点不对 | 发生什么具体事件时，你会需要它？ |
| 流程摩擦 | 如果支付和签约摩擦现在消失，你会立刻付款吗？仍不会的原因是什么？ |

这些回答是定性归因线索，不得伪装成统计结论。

## 五、交付与结果记录

- 约定动作是否真实完成；
- 最早外部信号、出现时间和成本；
- 用户是否复购、转介绍或允许公开评价；
- 每单杨的准备、判断、沟通和复盘小时数；
- 失败损失属于现金、时间、机会还是稀缺关系；
- 哪些价值来自可复述流程，哪些来自杨个人经验、关系或超额投入。

个人手艺风险只登记，不自动判失败；是否是一门好生意与能否形成组织分开裁决。

## 六、禁止动作

在杨另行授权前，不生成招募文案、不列真人名单、不联系用户、不设价格、不收款，也不以“先跑起来”为由绕过竞品消化、E000和购买情境推演。

## 七、重新启动时必须回答

1. 我们究竟复制了哪类竞品的价值结构？
2. 这句合法购买情境是什么，哪项仍为`H/Ø`？
3. 付款方当前为哪个替代方案付钱或承担成本？
4. 交付后多久能看到什么外部信号？
5. 用户用已有通用模型，在相近时间、成本和风险下能否复现？
6. 这一版本只采用哪一种风险承担方式？
7. 什么结果会停止、降级或改写实验？
